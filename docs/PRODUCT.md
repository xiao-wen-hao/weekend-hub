# 产品概念与流程

周末局处理熟人间零散、不完整、未必同步表达的活动想法。它把“可能一起做什么”转为“是否值得讨论”，再推动具体安排。当前范围是小圈子聚餐加一项娱乐或户外活动；不提供场地预订，也不替人作参加承诺。

| 概念 | 含义 | 不代表 |
| --- | --- | --- |
| Intent 意愿 | 某人在圈内对活动的自然语言表达；可模糊、可撤回 | 承诺参加、发起讨论 |
| Discussion Room 讨论间 | 多人对一次机会的共享公告、私聊、方案与投票空间 | 活动已确定、所有人已报名 |
| Proposal/Plan 方案 | 某一版本的日期、区域和分项安排；由成员确认 | 旧确认自动沿用到新版 |

## 让局产生

本人输入自然语言 → 服务端提取方向和条件 → 本人核对、确认并分别授予匹配/联系权限 → 圈内产生候选建议 → 各成员选择是否讨论 → 发起人明确开房，受邀者明确加入。见 `server/server/community.ts`、`intent-parser.ts`、`semantic-match.ts`。

## 让局成行

成员在房间表达意见 → 共享公告记录有授权的公共内容 → 协调器生成草案 → 模型识别有来源依据的冲突并向相关成员提问 → 回答触发重新分析 → 必要时投票 → 成员确认**当前** proposal ID → 分项报名。方案变化后旧确认不计入新版。见 `server/server/index.ts`、`coordinator.ts`、`semantic-coordination.ts`。

成员可以拒绝邀请、退出方案决策、拒答问题或不报名某一分项。沉默不算接受。私人 AI 会话默认只有本人可读；公共分享须原作者显式批准，历史私聊不会自动公开。模型可利用私人条件作内部分析，但返回给其他成员的公告和解释按权限裁剪。继续阅读 [LLM](LLM.md) 和 [数据与 API](DATABASE_AND_API.md)。
