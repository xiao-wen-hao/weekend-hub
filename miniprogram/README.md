# 周末局微信小程序（产品版）

独立的 Taro 4 + React 客户端。首页、熟人圈、自然语言意愿、候选局、讨论间、投票、逐人确认和分项报名调用同一个 Express + SQLite 后端。小程序与 Web 共用业务规则。

## 本地运行与手动验收

1. 在 `server/` 运行 `npm install`、`npm run dev`。确认浏览器可访问 `http://127.0.0.1:3000/api/health`。
2. 在 `miniprogram/` 运行 `npm install`、`npm run typecheck`、`npm test`、`npm run build:weapp`。
3. 用微信开发者工具选择 **导入项目**，项目目录选择 `miniprogram/`。`project.config.json` 的 `miniprogramRoot` 已指向 `dist/`，AppID 暂为 `touristappid`。
4. 在开发者工具中启用本地调试所需的“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”。登录页后端地址填 `http://127.0.0.1:3000`；若网络环境不能访问此地址，填开发者工具可访问的后端地址。
5. 用 `server/DEMO.md` 中的测试账号登录。检查首页圈子、待办和最近的局；进入圈子，核对意愿、候选局和成员；创建或加入圈子后试用自然语言解析，**先核对再确认投递**；候选局三人同意后进入房间。
6. 在房间检查公告、方案版本、私人条件、私聊、投票、逐人确认和分项报名。用另一个账号在 Web 打开同一房间，核对当前方案版本与报名状态，并确认私人消息没有泄漏。
7. 从房间分享路径打开小程序；未登录时应先进入登录页，登录后返回指定房间。分享圈子会携带邀请码，接收者需主动点“加入”。

`api-client.test.mjs` 验证 Bearer Token、401/403、网络错误和分享登录目标恢复。`weapp-flow.integration.mjs` 可在隔离的 `3107` 测试服务上检查真实 API 的意愿、候选局、房间以及 Web/小程序会话数据一致性。编译与自动 API 测试不能代替开发者工具模拟器或真机验收。

## 当前平台边界

- 当前使用后端账号密码与独立 Bearer Token；正式 `wx.login` 身份绑定尚未接入。
- 订阅消息、正式 AppID、真机请求合法域名和 HTTPS 配置尚未完成。
- 现有意愿解析 API 结构化提取活动类别和时段；预算保留在原话中，房间讨论支持分项预算协调。
- 候选局 API 在开启前仅返回人数与匹配依据，不公开其他候选成员身份；开启后房间显示成员。
