# 周末局本地示例

## 事先准备

在 `server/` 内安装依赖后，给后端设置独立的 `DATA_DIR`，启动 `npm run dev`。配置 `TOKENDANCE_API_KEY` 后，私聊会调用模型；模型不可用时自动改用基础识别，并在私聊中标明来源。密钥只放环境变量或 git 忽略的 `.env`。

运行 `npm run demo:seed`，终端会输出本次讨论间链接。脚本通过注册、熟人圈、自然语言意愿、候选局、明确接受讨论邀请、私人消息和授权公开的想法 **真实 API** 创建数据，不用 Mock。测试账号为 `demo_aqing`（阿青）、`demo_xiaolin`（小林）、`demo_qixi`（七喜）、`demo_mumu`（木木）；密码均为 `DemoPass1234`，仅用于隔离的本地示例数据库。

## 现场路径（约 4 分钟）

1. 用阿青登录 Web，打开脚本给出的讨论间。展示第一版到协商版的公开记录，以及仅本人可见的私人条件。
2. 用小林登录另一个浏览器窗口。展示“21 点前离开、不吃火锅、聚餐最多 100 元”的私聊；阿青侧只看见协调后的烤肉与预算 100 元，不看见小林的原话。
3. 阿青在公告牌发起“吃什么”匿名投票；四个账号依次投票，展示票数与更新后的方案版本。
4. 四人对当前版本点“我能接受这版”；如方案变更，旧确认必须重新做。每人分别对聚餐与桌游点“我参加”或“这段不来”。
5. 展示房间最终“已定案”、分项报名名单，以及另一个账号刷新后看到同一方案。

要自动核对这条完整链路，设置 `DEMO_COMPLETE=1` 后运行 `npm run demo:seed`。脚本会优先复用最近的未定案演示局；若已有四人定案局，则直接重复核验，不再创建同名房间。协调完成后投票、确认和报名，等待后再次读取四人的当前方案与报名，只有稳定保持 `phase: final`、同版 4 人接受和 8 条报名才以零退出码结束。普通 `demo:seed` 会复用未定案局；需要刻意新开一局时设置 `DEMO_FRESH=1`。脚本不会删除已有圈子或房间。

## 多端

Web：`npm run dev`；Android：`npm run sync:android` 后打开 `server/android`；微信：在 `miniprogram/` 运行 `npm run build:weapp` 后用微信开发者工具导入。Android 模拟器默认后端地址是 `10.0.2.2:3000`。小程序登录页填写可访问的后端地址。两端使用同一套真实 API 与数据库。
